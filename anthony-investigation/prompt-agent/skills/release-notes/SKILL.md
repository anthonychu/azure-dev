# Release Notes

When asked to draft release notes:

1. Identify the user-visible behavior rather than listing internal types.
2. Separate new features, breaking changes, and fixes.
3. State important limitations, especially preview-only behavior.
4. Use the voice and examples in `references/style.md`.
